# SciDocGym v0.1 Specification

Status: **Normative POC contract**  
Issue: **#33 — T01: Write the SciDocGym v0.1 specification**

The terms **MUST**, **MUST NOT**, **REQUIRED**, **SHOULD**, and **MAY** are normative.

## 1. Objective

SciDocGym v0.1 is an RL environment and benchmark for reconstructing structured scientific documents from rendered scientific PDF pages.

The **primary v0.1 RL unit is one page**.

Each training episode:

1. exposes one rendered page;
2. asks the model for a page-scoped DoclingDocument prediction;
3. deterministically compares that prediction with hidden gold;
4. returns a scalar reward and component diagnostics.

Full-document reconstruction remains a required benchmark but is not the primary optimization unit.

The canonical pipeline is:

```text
real PMC JATS
    ↓
admission + rights + provenance
    ↓
JATS-RL 0.1
   ↙       ↘
gold       semantic HTML
Docling    ↓
Document   Vivliostyle
   ↑       ↓
   └── layout trace
         ↓
PDF + verified gold DoclingDocument
         ↓
page-level OpenEnv / RLVR
         ↓
train only on train articles
         ↓
held-out synthetic evaluation
         +
held-out publisher-PDF evaluation
```

Semantic gold MUST NEVER be generated by applying OCR or a PDF parser to the generated PDF.

# 2. Corpus

SciDocGym v0.1 contains exactly:

- **30 admitted PMC Open Access research articles**;
- **20 train articles**;
- **5 validation articles**;
- **5 test articles**.

Every article MUST have:

- PMCID;
- DOI when available;
- source JATS;
- required assets;
- publisher PDF;
- machine-readable rights information;
- cryptographic hashes;
- retrieval provenance.

The corpus collectively MUST exercise:

- paragraphs;
- at least two section levels;
- lists;
- figures;
- captions;
- tables;
- inline math;
- display math;
- citations;
- reference lists;
- short and long articles.

No single article is required to contain every structure.

---

# 3. Split policy

Splitting occurs strictly at **article level**.

No artifact derived from the same PMCID may cross a split boundary.

This includes:

- pages;
- generated PDFs;
- themes;
- degraded variants;
- HTML;
- gold DoclingDocuments;
- page-level episodes;
- natural publisher PDFs.

The initial split is generated deterministically by:

```text
key = SHA256("scidocgym-v0.1-split\0" || PMCID)
```

Sort the 30 PMCIDs lexicographically by `key`.

Assign:

```text
1–20  → train
21–25 → validation
26–30 → test
```

Ties are broken lexicographically by PMCID.

Once committed, the split manifest is authoritative.

A change in corpus membership requires a new dataset version and regeneration of the entire split.

The following are forbidden:

- training on validation or test pages;
- SFT using validation/test gold;
- checkpoint selection using test reward;
- optimization using publisher PDFs from test articles;
- exposing gold JATS, source IDs, layout traces, or gold Docling JSON to the agent.

Automated tests MUST show:

```text
PMCID overlap across splits = 0
derived-artifact overlap across splits = 0
```

## Unsupported content

Unsupported content has exactly three possible outcomes.

### Lossless flattening

An unsupported inline wrapper MAY be removed when doing so preserves:

- all descendant visible text;
- formulae;
- references;
- order.

A structured warning MUST be emitted.

### Ignored metadata

Non-rendered metadata MAY be omitted when it changes neither visible content nor supported semantic relations.

### Rejection

If flattening or omission would lose:

- visible text;
- section/list structure;
- table semantics;
- formula semantics;
- figure/caption information;
- reference identity;

the article MUST be rejected.

Therefore:

```text
allowed information-losing unsupported semantic structures = 0
```

# 5. Full-document gold

Gold is a valid DoclingDocument compiled **directly from JATS-RL**.

Required mapping:

| JATS-RL | Docling |
|---|---|
| article title | `title` |
| section title | `section_header` |
| paragraph | `paragraph` / documented `text` context |
| list | list group |
| list item | `list_item` |
| figure | `picture` |
| caption | `caption` linked to floating item |
| table | `table` + `TableData` |
| formula | `formula` |
| bibliography entry | `reference` |
| cross-reference | deterministic relation to target |

Contributor and affiliation display text MUST remain represented in reading order even when the pinned Docling schema has no dedicated author/affiliation type.

Gold compilation MUST satisfy:

```text
supported node coverage          = 100%
normalized supported text        = 100%
orphan nodes                     = 0
broken references                = 0
duplicate mapped source IDs      = 0
invalid table spans              = 0
missing supported formulae       = 0
```

Compilation of identical canonical input MUST produce byte-identical canonical output.

Gold generation fails if any invariant fails.

# 6. Layout gold

Every traceable semantic HTML object carries:

```html
data-scidoc-id="..."
```

Rendering MUST produce fragment-level layout traces.

Each fragment contains:

```json
{
  "source_id": "...",
  "page_no": 3,
  "fragment_index": 0,
  "bbox": "...",
  "charspan": [125, 203]
}
```

`charspan` is `[start_inclusive, end_exclusive)`.

It is REQUIRED for text-bearing elements split:

- across several boxes;
- across columns;
- across pages.

This is essential because page-level gold MUST contain only text actually visible on the observed page.

Renderer coordinates are deterministically converted to Docling coordinates.

The v0.1 canonical coordinate origin is:

```text
TOPLEFT
```

All resulting coordinates MUST be finite and inside their page.

---

# 7. Page-level gold

For page `p`, page gold is derived from:

```text
full semantic gold + renderer layout trace
```

and NEVER by PDF parsing.

An item is included when:

- it has at least one visible provenance fragment on page `p`; or
- it is a structural ancestor required to connect visible descendants.

For an item split across pages, its page-level `text` is only:

```text
concatenation of charspans visible on p
```

in renderer order.

Pure structural ancestors MAY appear without geometry.

Hidden gold MUST NOT expose to the agent:

- source IDs;
- original JATS IDs;
- provenance map;
- full-document text outside the page;
- gold JSON pointers.

# 8. Observation

The agent receives:

```json
{
  "schema_version": "scidocgym.observation/0.1",
  "task_id": "opaque-string",
  "page": {
    "page_no": 1,
    "page_count": 12,
    "width_px": 1240,
    "height_px": 1754,
    "dpi": 150,
    "mime_type": "image/png",
    "image_base64": "..."
  },
  "render": {
    "source_kind": "synthetic",
    "theme": "single-column",
    "degradation": "clean"
  }
}
```

Definitions:

`schema_version`
: literal `scidocgym.observation/0.1`.

`task_id`
: deterministic opaque episode identifier. It MUST NOT reveal PMCID, split, source IDs, labels, or gold counts.

`page_no`
: 1-based integer satisfying:

```text
1 <= page_no <= page_count
```

`page_count`
: integer `>= 1`.

`width_px`, `height_px`
: positive integers.

`dpi`
: positive integer recorded in the episode manifest.

`mime_type`
: literal `image/png`.

`image_base64`
: standard base64 of the exact PNG bytes.

`source_kind`
:

```text
synthetic
publisher_pdf
```

`theme`
:

```text
single-column
double-column
publisher
```

`degradation`
:

```text
clean
rasterized-recompressed
publisher-native
```

The observation MUST NOT expose:

- PMCID;
- JATS/XML;
- gold text;
- source IDs;
- gold object count;
- gold labels;
- layout traces;
- gold Docling JSON;
- reward targets.

# 9. Action

The action is UTF-8 JSON representing a **page-scoped subset of DoclingDocument**.

It MUST validate against the pinned v0.1 prediction schema.

Permitted top-level fields:

```text
schema_name
version
name
origin
body
furniture
groups
texts
pictures
tables
pages
```

Unsupported top-level Docling arrays MUST be absent or empty.

`schema_name` MUST equal:

```text
DoclingDocument
```

The model is never required to reproduce gold IDs.

Prediction `self_ref` values only need to be valid and internally consistent within the submitted prediction.

## Scored labels

The v0.1 scorer recognizes:

```text
title
section_header
paragraph
text
list_item
picture
caption
table
formula
reference
page_header
page_footer
```

Other Docling labels receive no semantic credit and count as unmatched predictions.

## Text items

Scored text is `text`.

`orig` remains required whenever required by the pinned Docling schema.

For section headers:

```text
level >= 1
```

For list items:

```text
enumerated: boolean
marker: visible marker or ""
```

## Formulae

Formula text uses canonical MathML serialized as UTF-8 XML.

Namespace-prefix differences and deterministic XML formatting are canonicalized before evaluation.

## Tables

Tables use Docling `TableData`.

Required fields include:

```text
num_rows
num_cols
orientation
table_cells
```

Each cell includes:

```text
text
start_row_offset_idx
end_row_offset_idx
start_col_offset_idx
end_col_offset_idx
row_span
col_span
column_header
row_header
row_section
```

All offsets and spans MUST stay inside the declared table dimensions.

## Provenance

Each content provenance record contains:

```json
{
  "page_no": 1,
  "bbox": {
    "l": 10,
    "t": 20,
    "r": 300,
    "b": 80,
    "coord_origin": "TOPLEFT"
  },
  "charspan": [0, 42]
}
```

Requirements:

```text
page_no == observed page_no
0 <= l <= r <= page_width
0 <= t <= b <= page_height
0 <= charspan.start <= charspan.end <= len(text)
```

# 10. Invalid action

The complete reward is exactly zero if:

- UTF-8 is invalid;
- JSON is invalid;
- prediction schema validation fails;
- local references dangle;
- forbidden cycles exist;
- provenance targets another page;
- coordinates are non-finite;
- coordinates leave the page;
- charspans are invalid;
- table geometry is invalid.

Then:

```text
T = B = O = S = M = L = R = 0
```

A deterministic error category MAY be returned.

It MUST NOT reveal hidden gold.

---

# 11. Deterministic matching

Models do not reproduce gold IDs.

Predicted and gold content blocks are paired using deterministic maximum-weight bipartite matching.

For prediction `i` and gold `j`:

```text
Q(i,j) =
    0.45 * X(i,j)
  + 0.35 * P(i,j)
  + 0.20 * Y(i,j)
```

where:

- `X`: textual/signature similarity;
- `P`: relative-position similarity;
- `Y`: block-label equality.

`Y = 1` when labels agree and `0` otherwise.

For text similarity, normalize Unicode and tokenize using:

```regex
\w+|[^\w\s]
```

Tokens remain:

- case-sensitive;
- punctuation-sensitive;
- digit-sensitive.

Text F1 is based on longest-common-subsequence token alignment.

Position:

```text
P = 1 - min(1, center_distance / page_diagonal)
```

using the union of item bounding boxes.

If either side has no visible provenance:

```text
P = 0
```

Matches with:

```text
Q < 0.25
```

are discarded.

Ties are resolved deterministically using gold preorder index followed by prediction preorder index.

# 12. Reward

The reward is exactly:

```text
R =
    0.30 T
  + 0.20 B
  + 0.15 O
  + 0.15 S
  + 0.10 M
  + 0.10 L
```

Each component is in `[0,1]`.

## T — text/span F1

Micro token F1 over:

```text
title
section_header
paragraph
text
list_item
caption
reference
page_header
page_footer
```

Unmatched predicted tokens are false positives.

Unmatched gold tokens are false negatives.

Formula/table text is excluded because it is evaluated by M.

When neither side contains applicable text:

```text
T = 1
```

When only one side contains it:

```text
T = 0
```

## B — block-type F1

Micro F1 over v0.1 content labels.

Correct matched type:

```text
TP += 1
```

Wrong type:

```text
FP(predicted type) += 1
FN(gold type) += 1
```

Unmatched prediction:

```text
FP += 1
```

Unmatched gold:

```text
FN += 1
```

## O — reading order

Let:

```text
m   = matched body blocks
Pb  = predicted body blocks
Gb  = gold body blocks
```

Coverage:

```text
C = 2m / (Pb + Gb)
```

Pairwise order agreement `A` is the fraction of matched item pairs whose relative body-preorder ordering agrees.

Then:

```text
O = C * A
```

This prevents an agent from obtaining high reading-order reward by predicting only a tiny subset.

## S — structure/tree

Serialize body structure by preorder traversal.

Tokens include:

```text
OPEN:<group-label>
ITEM:<content-label>
ITEM:section_header:LEVEL=<n>
ITEM:list_item:ENUM=<0|1>
CLOSE:<group-label>
```

Caption attachment relations are also represented.

Excluded from structural tokens:

- IDs;
- JSON pointers;
- text;
- geometry;
- source names.

`S` is token F1 between prediction and gold structural sequences.

## M — table/math

```text
M = 0.5 * M_table + 0.5 * M_math
```

### Tables

For each matched table:

```text
table_score =
    0.20 * dimension_score
  + 0.35 * cell_structure_f1
  + 0.45 * cell_text_f1
```

`dimension_score = 1` iff both row and column counts match.

Cells are structurally identified by:

```text
start_row
end_row
start_col
end_col
column_header
row_header
row_section
```

Unmatched tables score zero.

If both sides contain no table:

```text
M_table = 1
```

### Math

Canonical MathML is compared after normalization of:

- namespaces;
- attribute order;
- XML whitespace;
- Unicode NFC.

Formula pairs use token F1.

Unmatched formulae score zero.

If both sides contain no formulae:

```text
M_math = 1
```

## L — layout

For every matched item, predicted and gold fragments are maximum-IoU matched.

Item layout score:

```text
sum(matched IoU)
-----------------------------
max(pred_fragment_count,
    gold_fragment_count)
```

Unmatched fragments contribute zero.

`L` is the mean over all layout-relevant item slots.

# 14. Full-document benchmark

Full-document reconstruction remains required.

Two modes are permitted.

## Native

The model consumes the ordered complete PDF and returns one DoclingDocument.

## Page assembly

Page predictions are generated independently and assembled deterministically.

Assembly MUST:

- re-index local JSON pointers;
- union pages by page number;
- concatenate page body roots in page order;
- avoid speculative merging of cross-page nodes.

Cross-page merging MAY be evaluated separately but does not affect page-level RL reward.

Reports MUST state which mode was used.

# 16. Measurable POC gates

## Gate A — corpus and split

PASS iff:

```text

train                           = 20
validation                      = 5

cross-split PMCID overlap       = 0
derived-artifact overlap        = 0

```

## Gate B — canonical JATS-RL

PASS iff for all 30 articles:

```text
schema validation failures = 0
canonicalization idempotence failures = 0
non-deterministic hash failures = 0
```

## Gate C — semantic gold

PASS iff:

```text
supported node mapping coverage = 100%
normalized text conservation    = 100%
orphan nodes                    = 0
broken references               = 0
invalid table spans             = 0
missing supported formulae      = 0
```

## Gate D — layout provenance

PASS iff:

```text
coverage >= 99.5%
out-of-page boxes = 0
invalid page indices = 0
silently dropped required objects = 0
```

Coverage denominator:

```text
all rendered source objects declared requires_provenance=true
```

Numerator:

```text
those objects with >=1 valid layout fragment
```

Every object in the remaining `<=0.5%` MUST be explicitly listed.

## Gate E — blinded visual QA

Exactly 50 generated pages.

At least:

```text
25 single-column
25 double-column
```

At least two reviewers.

Each rates:

```text
broken_layout: yes/no
major_overlap: yes/no
table_readable: yes/no when applicable
formula_readable: yes/no when applicable
scientific_publication_plausibility: 1–5
```

PASS iff:

```text
broken pages                       = 0
major-overlap pages                = 0
unreadable applicable tables      = 0
unreadable applicable formulae    = 0
overall median plausibility       >= 4
minimum per-page median           >= 3
```

## Gate F — anti-reward-hacking

Required regression fixtures:

| Prediction | Gate |
|---|---:|
| invalid JSON | `R = 0` |
| empty valid output | `R <= 0.10` |
| duplicate everything | cannot score above single-copy version |
| all text in one block | `R <= 0.45` |
| visible-text-only | `R <= 0.55` |
| deliberately disjoint/random bboxes | `L <= 0.10` |
| correct text, reversed reading order | `T >= 0.95`, `O <= 0.25` |
| correct structure, empty text | `S >= 0.95`, `T = 0` |
| exact gold-equivalent prediction | `R = 1.0` within serialization precision |

Every fixture MUST pass.

## Gate G — RL proof

Pipeline:

```text
base
→ optional SFT
→ checkpoint immediately before RL
→ GRPO
→ frozen held-out test
```

Primary gate:

```text
mean(R_after) - mean(R_before) >= 0.05
```

Test articles MUST NEVER participate in:

- optimization;
- checkpoint selection.

Invalid output rate MUST not worsen.

If:

```text
invalid_before > 0
```

then:

```text
invalid_after <= invalid_before - 1
```

If:

```text
invalid_before = 0
```

then:

```text
invalid_after = 0
```

Seeds, configs, prompts, curves, checkpoints, predictions, component scores, and manifests MUST be preserved.

## Gate H — natural publisher-PDF transfer

The five test publisher PDFs are never used for optimization.

Synthetic layout gold is not valid publisher layout gold.

Therefore `L` is excluded.

Natural score:

```text
R_natural =
(
  0.30T +
  0.20B +
  0.15O +
  0.15S +
  0.10M
) / 0.90
```

Gate:

```text
mean(R_natural_after)
>=
mean(R_natural_before)
```

Any regression blocks the claim that v0.1 transfers without degradation to real publisher PDFs.

# 21. Project-level Definition of Done

SciDocGym v0.1 is complete only when **all eight** statements hold.

## DoD 1 — Real, legal, leakage-free corpus

Exactly 30 admitted PMC OA research articles have complete rights, provenance, and hash records, with a deterministic 20/5/5 article split and zero derived-artifact leakage.

## DoD 2 — Canonical JATS-RL source truth

All 30 articles normalize deterministically into valid JATS-RL 0.1; canonicalization is idempotent and no information-losing unsupported semantic construct is silently removed.

## DoD 3 — Verified semantic gold

Direct JATS-RL compilation maps 100% of supported semantic objects, conserves 100% of supported normalized text, creates zero orphan nodes and broken references, preserves supported tables/formulae, is deterministic, and uses no OCR/PDF parser to generate gold.

## DoD 4 — Plausible synthetic PDFs with verified provenance

Both themes successfully render the POC corpus, 50-page blinded QA passes, layout coverage is at least 99.5%, out-of-page boxes and invalid page indices equal zero, and no required rendered object is silently dropped.

## DoD 5 — Valid RL environment and non-trivial reward

The page-level task runs through the packaged OpenEnv environment, gold remains hidden, all six reward components are deterministic and defined, an exact gold prediction scores 1.0, and every anti-reward-hacking regression passes.

## DoD 6 — Common reproducible baselines

B0, B1, B3, B4 and B2 when applicable run against identical frozen evaluation manifests and scorer, with persisted predictions, component scores, versions, configurations, and separate synthetic/natural reports.

## DoD 7 — Demonstrated RL improvement

On the frozen unseen synthetic test set:

```text
mean(R_after) - mean(R_before) >= 0.05
```

and the invalid-output-rate condition is satisfied, with no test article used for optimization or model selection.

## DoD 8 — No real-PDF regression and reproducible release

On the five held-out publisher PDFs:

```text
mean(R_natural_after)
>=
mean(R_natural_before)
```

and the published release includes enough environment, dataset/materialization information, manifests, hashes, configurations, rights records, model/checkpoint artifacts, and documentation for a clean machine to:

1. build SciDocGym;
2. run baseline evaluation;
3. reproduce at least one complete episode.
